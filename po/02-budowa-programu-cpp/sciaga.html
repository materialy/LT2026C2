Zanim zaczniesz

  • Kod piszesz w pliku main.cpp w projekcie konsolowym IDE.
  • F9 (Build and run) buduje program i od razu go uruchamia.
  • Błędy kompilacji widać w panelu Build messages razem z numerem linii.
  • Linię „Process returned 0 (0x0)” dopisuje IDE po zakończeniu programu.

Każdy program w C++ ma ten sam szkielet. Tu poznasz rolę każdej linii programu „Hello world!” i zasady zapisu, których kompilator pilnuje bez wyjątków.

01Szkielet programu linijka po linijce

#include <iostream>     // dołącz bibliotekę wejścia/wyjścia (cout, cin)

using namespace std;      // używaj nazw ze std bez przedrostka std::

int main()               // funkcja główna, zwraca liczbę całkowitą
{                        // początek ciała funkcji
    cout << "Hello world!" << endl;   // instrukcja: wypisz napis
    return 0;            // koniec programu, 0 = sukces
}                        // koniec ciała funkcji

02Funkcja main i return

Zawsze int main()

Standard C++ wymaga, żeby main zwracała int. Inny typ to błąd kompilacji.

return to kod wyjścia

return 5; nie zmieni wyniku na ekranie, ale IDE pokaże Process returned 5 (0x5). Liczba różna od 0 oznacza dla systemu błąd.

string main()     // BŁĄD: main musi zwracać int
{
    cout << "Hello world!" << endl;
    return 0;
}
// Build messages: error: '::main' must return 'int'

03Zasady zapisu

  • C++ rozróżnia wielkie i małe litery: main to nie Main, a cout to nie Cout.
  • Średnik kończy instrukcję. Nie stawiamy go po #include ani zaraz po int main().
  • Każda klamra { musi mieć swoją parę }.
  • Spacje, entery i wcięcia kompilator pomija (poza tekstem w cudzysłowie). Wcięcia piszemy dla ludzi.
  • Komentarz // … trwa do końca linii, a /* … */ może zająć kilka linii. Kompilator go pomija.

04Typowe błędy

  • int main();: średnik kończy linię, a klamra { pod spodem nie ma do czego należeć.
  • Int main() albo int Main(): zła wielkość liter. Int to nieznany typ, a bez funkcji main program nie powstanie.
  • #include <iostream>;: zbędny średnik, kompilator wypisze ostrzeżenie.
  • Zapomniany średnik na końcu instrukcji: błąd expected ';' before ….

06Sprawdź się

Odpowiedz w myślach, potem rozwiń.

Dlaczego po #include <iostream> nie stawiamy średnika?

To nie instrukcja C++, tylko polecenie dla preprocesora. Kończy się razem z linią.

Od której linii zaczyna się wykonywanie programu?

Od pierwszej instrukcji wewnątrz main, a nie od pierwszej linii pliku.

Jak zapisać komentarz na trzy linie?

/* linia 1 … linia 3 */ albo trzy razy // na początku linii.

Ile klamer } musi być w programie „Hello world!”?

Jedna, bo jest jedna klamra otwierająca { po int main().

trudniejsze Czy skompiluje się int main(){cout<<"A";return 0;} zapisane w jednej linii (z #include i using wyżej)?

Tak. Białe znaki nie mają znaczenia, ale taki kod trudno czytać.

trudniejsze Co zobaczysz w konsoli po zmianie return 0; na return 7;?

Ten sam napis. Zmieni się tylko linia dopisana przez IDE: Process returned 7 (0x7).

trudniejsze Co się stanie, gdy dopiszesz instrukcję cout pod return 0;, ale przed }?

Program się skompiluje, ale ta instrukcja nigdy się nie wykona, bo return kończy main wcześniej.
