IDE to program, w którym piszesz kod, budujesz z niego działający program i czytasz komunikaty o błędach. Przykłady pokazujemy w Code::Blocks, ale w innych IDE wygląda to podobnie.

01Od kodu do programu

Komputer nie rozumie tekstu z pliku main.cpp. Zanim program ruszy, kod przechodzi przez cztery etapy:

EtapCo się dziejeCo powstaje
1. Pisanie kodupiszesz w edytorze IDEmain.cpp, czyli kod źródłowy
2. Kompilacjakompilator (np. GCC) tłumaczy kod na język procesoramain.o, czyli plik obiektowy
3. Linkowanielinker łączy Twój kod z bibliotekamiTest.exe, czyli plik wykonywalny
4. Uruchomieniesystem uruchamia program w oknie konsolinapis w konsoli

Co jest w IDE

Edytor z kolorowaniem składni, kompilator, debuger (szukanie błędów krok po kroku) i menedżer projektu. Wszystko w jednym oknie.

Przykłady IDE do C++

Code::Blocks, Visual Studio, CLion, Dev-C++. Kod w C++ jest ten sam, różnią się przyciski i menu.

02Nowy projekt w Code::Blocks

KrokCo klikasz
1File → New → Project…
2Console application → Go, potem język C++
3nazwa projektu (np. Test) i folder, najlepiej bez spacji i polskich liter
4kompilator GNU GCC Compiler → Finish
5w panelu Projects: Sources → main.cpp (dwuklik otwiera plik)

IDE od razu wpisuje do main.cpp gotowy program. Szczegóły każdej linii poznasz w zagadnieniu o budowie programu:

#include <iostream>   // dołącz bibliotekę do wypisywania na ekran

using namespace std;    // pozwala pisać cout zamiast std::cout

int main()             // funkcja main: tu startuje program
{
    cout << "Hello world!" << endl;  // wypisz napis i zejdź linię niżej
    return 0;           // zakończ program, 0 = wszystko w porządku
}

03Przyciski, skróty i komunikaty

PolecenieSkrótCo robi
BuildCtrl+F9kompiluje i linkuje, ale nie uruchamia
RunCtrl+F10uruchamia ostatnio zbudowaną wersję
Build and runF9buduje i od razu uruchamia
RebuildCtrl+F11buduje wszystko od zera

Po uruchomieniu IDE dopisuje pod wynikiem programu linie Process returned 0 (0x0) i Press any key to continue. Liczba 0 to wartość z return 0;.

error (błąd)

Program nie powstanie. W panelu Build messages widzisz plik, numer linii i opis, np. main.cpp | 7 | error: expected ';' before 'return'.

warning (ostrzeżenie)

Program powstanie, ale kompilator uważa, że coś jest podejrzane. Przeczytaj i popraw.

Poprawiaj błędy od pierwszego na liście, bo kolejne często są tylko jego skutkiem. Dwuklik na komunikacie przenosi do linii w edytorze.

04Typowe błędy

  • Zmieniasz kod i klikasz tylko Run, więc widzisz starą wersję. Używaj F9.
  • Folder projektu ze spacją lub polskimi literami (np. Moje Pliki/żółw). Kompilator może zgłaszać dziwne błędy.
  • Plik Test.exe uruchomiony dwuklikiem „miga” i znika: program skończył pracę, więc okno się zamknęło.
  • Nie zamknięto okna działającego programu. Nowego Test.exe nie da się zapisać (np. Permission denied).

06Sprawdź się

Odpowiedz w myślach, potem rozwiń.

Czym różni się Build od Build and run?

Build tylko tworzy plik .exe. Build and run (F9) dodatkowo od razu go uruchamia.

Który plik otworzysz, żeby wrócić do całego projektu w Code::Blocks?

Plik projektu Test.cbp. Otworzy się z drzewem plików i ustawieniami.

Kto wypisał w konsoli linię „Process returned 0 (0x0)”?

IDE, nie Twój program. Dopisuje ją po zakończeniu programu i pokazuje wartość z return.

Co oznacza gwiazdka przed nazwą karty *main.cpp?

Plik ma niezapisane zmiany. Zapisz go Ctrl+S (Build też zapisuje pliki).

trudniejsze W Build messages jest 5 błędów. Od którego zacząć i dlaczego?

Od pierwszego. Jeden brakujący znak potrafi wywołać kilka kolejnych komunikatów. Po poprawce zbuduj ponownie, bo część zniknie.

trudniejsze Kolega skopiował na pendrive tylko Test.exe, żeby w domu poprawić program. Co poszło nie tak?

Pliku .exe nie da się edytować, bo to kod maszynowy. Do poprawek potrzebny jest main.cpp, najlepiej cały folder projektu.

trudniejsze Build skończył się komunikatem „0 error(s), 1 warning(s)”. Czy program powstał?

Tak. Ostrzeżenie nie blokuje budowania, ale warto je przeczytać, bo często wskazuje prawdziwy błąd w logice.

07Spróbuj sam

  1. Utwórz projekt konsolowy C++ o nazwie Powitanie w folderze bez spacji i polskich liter. Uruchom go klawiszem F9.
    Podpowiedź

    File → New → Project… → Console application → C++, nazwa Powitanie, folder np. C:\cpp, kompilator GNU GCC, Finish.

  2. Zmień napis na "Witaj, Kot Filemon!". Najpierw kliknij tylko Run (Ctrl+F10), potem F9. Porównaj wyniki.
    Rozwiązanie

    Run pokaże stary napis „Hello world!”, bo program nie został przebudowany. Dopiero F9 pokaże nowy.

  3. Wklej do main.cpp plik startowy main.cpp. Zbuduj go, odczytaj z Build messages numery linii i popraw oba błędy.
    Rozwiązanie

    Na końcu linii z „zaprasza” brakuje średnika. W kolejnej linii jest Cout zamiast cout, a C++ rozróżnia wielkość liter.

        cout << "Sklep Pod Lipa zaprasza" << endl;
    cout << "Otwarte od 8 do 16" << endl;
  4. Znajdź w folderze projektu plik .exe i uruchom go dwuklikiem. Wyjaśnij, czemu okno od razu znika.
    Rozwiązanie

    Plik leży w bin/Debug. Program wypisuje napis i od razu się kończy. Okno trzyma otwarte tylko IDE („Press any key to continue”).
